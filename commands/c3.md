# C3 — Design Iteration Sprint

Use this chain for polishing existing UI: tightening animations, fixing responsive breakpoints,
improving visual hierarchy, or chasing a specific aesthetic. It skips heavy planning and goes straight
into iterative design-build cycles scored against a rubric.

## Chain

```
/model-route   Recommend the best model tier for this complexity and budget
/unified-design-system  Step 1: read MASTER.md and PREFERENCES.md; the redesign keeps to them
/hallmark redesign <path> polish   Record the page, pass MASTER.md as the system, fix only what the gates name, fresh-context review. Say "keep the layout" for a restyle, or nothing for a full redesign
/gan-build     Build loop: implement → evaluate → fix (score-gated)  [only for behaviour that needs a functional check: animation, interaction]
/quality-gate  Lint, type check, format — confirm nothing broke
/design-gate <path> --kept --tier floor   Fails if a link, field, handler or test hook the page had before is gone
/chelp-advisor Pre-ship review: stamp and waivers claim only what ran, the depth was not widened
/code-review   Final review pass before committing
```

## When to Use

- Improving visual polish on an existing page or component
- Animation and transition refinement
- Responsive layout fixes across breakpoints
- Dark mode / theme work

## Prerequisites

- **Hallmark** (design skill and gate): `npx skills add nutlope/hallmark -g`. Optional: without it `/design-gate` prints SKIPPED and the review checklist (unified-design-system step 6) is the gate.
- **Browser checks** for `--render` and `--require-render`: `npm i -g puppeteer-core` and Chrome. Playwright alone is not enough.

## Tips

- In an Astryx project, change the theme with `npx astryx experimental theme editor` and look at it with `--png` before you change components (`astryx-components` skill).
- `/chelp-advisor pre-ship c3` after the `--kept` check (see the `chelp-advisor` skill).
- Not sure what is wrong? Run `/hallmark audit <path>` first. It only reports.
- `/hallmark redesign` records the page before it starts (`sloplint --before`) and `/design-gate --kept --tier floor` re-checks it at the end. Run both from the same folder, on files with the same names.
- `--kept` compares the sets of links, form fields, handlers and test hooks recorded for the folder. A field or link that still appears on another page is not reported as missing, so it is a safety net, not a proof.
- Depth comes from the words in the brief: "polish" fixes only what the gates name, "restyle" or "keep the layout" changes the system, nothing changes the composition too. A redesign never drops a link, field or test hook.
- Use Hallmark's fast mode (`--fast`) for sprints where the direction is already known.
- `/gan-design` is no longer in this chain. Add it back only for extra originality, and never let it overrule the Floor.
- Pass `--max-iterations 5` to `/gan-build` (default 15) for faster sprints when the design direction is already known.
- `/gan-build` defaults to playwright evaluation; add `--eval-mode screenshot` for purely visual assessment.

- When the user accepts, rejects or corrects a design choice, log it in `design-system/PREFERENCES.md` (unified-design-system step 7). The next run reads it in step 1.

## Usage

```
/c3 Polish the hero section — add a parallax scroll effect and tighten the mobile layout
```
