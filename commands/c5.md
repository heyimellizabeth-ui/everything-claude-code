# C5 — Maintenance and Cleanup

Use this chain after a feature ships, during a refactor sprint, or when the codebase has accumulated
dead CSS/JS, stale docs, or drifted architecture maps. It safely removes unused code, refreshes
documentation, and leaves a clean checkpoint.

## Chain

```
/refactor-clean  Detect and remove dead code — safe/caution/danger tiers with test verification
/update-codemaps Regenerate architecture docs so AI context reflects current structure
/update-docs     Sync CONTRIBUTING, RUNBOOK, and env docs from source-of-truth files
/quality-gate    Lint, type check, format — confirm nothing broke during cleanup
/checkpoint      Snapshot the clean state for future comparison
```

## When to Use

- Post-launch cleanup after a large feature ships
- Before a new feature sprint to start from a clean baseline
- When docs have drifted from the codebase
- Quarterly codebase health pass

## Tips

- `/refactor-clean` categorizes findings into SAFE, CAUTION, and DANGER — review CAUTION items manually.
- `/update-codemaps` will show a diff if changes exceed 30%; approve before it overwrites.
- `/checkpoint create post-cleanup` creates a named checkpoint you can verify against later with `/checkpoint verify post-cleanup`.
- Pass a path to `/refactor-clean` (e.g. `src/components`) to scope the cleanup rather than running it project-wide.

## Usage

```
/c5 src/components — clean up unused component files after the design system migration
```
